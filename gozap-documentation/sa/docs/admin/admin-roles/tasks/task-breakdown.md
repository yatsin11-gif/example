## Список задач

### Task 1

- Title: BE. Admin Roles. Модель ролей/уровней доступа и серверная авторизация
- Repository: `gozap-backend`
- Owner role: Backend engineer
- Зачем нужна задача: без серверной модели ролей и проверки доступа нельзя гарантировать, что администратор не получит данные недоступных разделов даже при обходе FE.
- Scope:
  - модель ролей: супер-админ (полный доступ), админ (уровень доступа)
  - создание администратора только от имени супер-админа с обязательным указанием уровня доступа
  - серверная проверка уровня доступа при обращении к ограниченным разделам/эндпоинтам
- Out of scope:
  - гранулярные права на уровне отдельных действий внутри раздела
  - аудит-лог действий администраторов
- Dependencies:
  - нет
- Risks:
  - точный список разделов и уровней доступа не подтверждён (open question)
- Definition of done:
  - супер-админ может создать администратора с уровнем доступа через API
  - запросы администратора к недоступным разделам отклоняются на backend

### Task 2

- Title: FE. Admin Roles. Создание администратора и условная навигация
- Repository: `gozap-admin`
- Owner role: Frontend engineer
- Зачем нужна задача: супер-админу нужен интерфейс создания администраторов, а администратору — навигация, ограниченная его уровнем доступа.
- Scope:
  - форма создания администратора с обязательным выбором уровня доступа (доступна только супер-админу)
  - условное отображение пунктов навигации по уровню доступа текущего пользователя
- Out of scope:
  - редактирование уровня доступа у уже созданного администратора (open question)
- Dependencies:
  - Task 1
- Risks:
  - нет
- Definition of done:
  - супер-админ может создать администратора с уровнем доступа
  - администратор видит в навигации только доступные ему разделы

## Порядок поставки

1. Task 1 — серверная модель ролей и авторизация.
2. Task 2 — FE создание администратора и условная навигация.
