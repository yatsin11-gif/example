## Роли в админке — визуальный TL;DR

Источник: [../requirements/feature-spec.md](../requirements/feature-spec.md). Схема — краткая суть, детали в спеке.

### User flow (что видит пользователь)

```mermaid
flowchart TD
    S1[Супер-админ: создать администратора] --> S2["Отметить разделы (множественный выбор):<br/>Станции / Пользователи / Партнёры"]
    S2 --> V{Хотя бы один раздел отмечен?}
    V -->|нет| ERR[Сохранение заблокировано]
    V -->|да| S3[Администратор создан с набором разделов]
    S3 --> EDIT[Данные и набор разделов<br/>после создания неизменны:<br/>супер-админ не может их отредактировать]
    EDIT --> L[Администратор логинится]
    L --> N["Боковое меню показывает<br/>только назначенные разделы<br/>(недоступные — полностью отсутствуют)"]
    N --> D{Прямой переход<br/>к неназначенному разделу?}
    D -->|да| BLOCK[Доступ отклонён]
```

### Что внутри (pipeline)

```mermaid
flowchart LR
    REQ[Запрос администратора к разделу] --> CHECK[Backend: входит ли раздел в назначенный набор?]
    CHECK -->|супер-админ| ALLOW[Доступ разрешён ко всему]
    CHECK -->|раздел не в наборе| DENY[Отклонено]
    CHECK -->|раздел в наборе| ALLOW
```

### Список разделов

```mermaid
flowchart LR
    STATIONS["Станции:<br/>создание, архивирование"]
    USERS["Пользователи:<br/>создание, промоаккаунт,<br/>блокировка, инфо + история аренд"]
    PARTNERS["Партнёры:<br/>создание, редактирование,<br/>список, баланс/выплата/аренды"]
```

> Вне итерации: гранулярные права внутри раздела, аудит-лог, делегирование роли супер-админа, редактирование данных/набора разделов администратора после создания. CRUD-логика разделов — в `admin/stations-management`, `admin/user-management`, `partners/partner-program`.
