## Проблема

- Сейчас нет способа разграничить, кто из сотрудников видит весь функционал админки, а кто — только ограниченный набор разделов.
- Супер-админу нужно заводить других администраторов и сразу определять, что им можно видеть.

## Цель

- Дать супер-админу возможность создавать администраторов и назначать им уровень доступа.
- Дать администратору доступ только к тем разделам админки, которые соответствуют его уровню доступа.

## Не входит в текущую итерацию

- Гранулярные права на уровне отдельных действий (только на уровне разделов).
- Самостоятельная регистрация администраторов без участия супер-админа.
- Аудит-лог действий администраторов.
- Передача/делегирование роли супер-админа.

## Триггер и аудитория

- Точка входа / триггер: супер-админ заходит в раздел управления администраторами и создаёт новую учётную запись с выбранным уровнем доступа.
- Основная аудитория: супер-админ.
- Вторичная аудитория: администраторы, которые логинятся и работают в рамках выданного доступа.

## Целевое поведение продукта

### Сценарий

1. Супер-админ открывает раздел управления администраторами и создаёт нового администратора, выбирая для него уровень доступа.
2. Администратор логинится в админку.
3. Администратор видит только те разделы, которые доступны его уровню доступа.

### Правила результата

- Супер-админ должен видеть и иметь доступ ко всем разделам админки без ограничений.
- Администратор не должен видеть разделы, не входящие в его уровень доступа.
- Создание администратора должно требовать явного выбора уровня доступа супер-админом.

## Бизнес-правила

- Существует минимум две роли: супер-админ (полный доступ) и админ (доступ ограничен выбранным уровнем).
- Уровень доступа назначается на этапе создания администратора супер-админом.
- Только супер-админ может создавать других администраторов.

## Пограничные сценарии

- Администратор пытается открыть раздел, недоступный его уровню доступа, напрямую по ссылке.

- Администратору меняют уровень доступа, пока он залогинен в активной сессии.

## Допущения

- Роли «супер-админ» и «админ» применяются к тому же продукту `gozap-admin`, где работает партнёрский кабинет, но являются отдельной ролевой осью от роли `partner`.
- Уровень доступа влияет на видимость целых разделов навигации, а не на отдельные элементы внутри раздела.
