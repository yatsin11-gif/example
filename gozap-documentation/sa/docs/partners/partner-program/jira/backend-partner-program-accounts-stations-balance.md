## Problem Statement

Сейчас нет backend-модели партнёра, привязки станций к партнёру, процента вознаграждения партнёра и расчёта начислений по периоду фактической привязки. Без этого фундамента невозможно построить статистику для администратора и партнёра.

## Scope

- CRUD учётной записи партнёра (логин, пароль, имя, телефон, процент вознаграждения), включая редактирование данных уже созданного партнёра
- список партнёров с поиском по логину (частичное совпадение) и сортировкой для администратора (по умолчанию по дате добавления от новых к старым; также по логину и по дате добавления по возрастанию/убыванию)
- привязка/отвязка одной или нескольких станций к партнёру
- хранение процента вознаграждения на уровне партнёра (применяется к прибыли со всех его станций), включая 0%
- гарантия, что станция привязана не более чем к одному партнёру одновременно
- начисление доли партнёра в баланс при завершении аренды по проценту партнёра, действовавшему на момент завершения
- учёт начислений только за период фактической привязки станции к партнёру, без пересчёта прошлого при отвязке/повторной привязке
- эндпоинты статистики: список станций партнёра, сводка за период, детализация аренд по станции

## Out of Scope

- интеграция со Stripe для выплат
- сброс пароля через SMS
- frontend-интерфейсы

## Implementation Notes

- affected modules: модуль партнёров/станций, модуль аренд/начислений backend (точные пути модулей `gozap-backend` требуют подтверждения при старте реализации)
- constraints: расчёт начисления должен быть идемпотентным относительно повторной обработки одной аренды
- known technical context: точная текущая схема станций и аренд в `gozap-backend` не исследована в рамках этого документа — подтвердить перед реализацией

## Acceptance Criteria

1. Администратор может создать партнёра с логином, паролем, именем, телефоном и процентом вознаграждения (включая 0%).
2. Администратор может отредактировать данные уже созданного партнёра (логин, имя, телефон, процент вознаграждения).
3. Администратор может искать партнёров по логину (частичное совпадение) и сортировать список по логину и по дате добавления (по умолчанию — по дате добавления от новых к старым).
4. Администратор может привязать/отвязать одну или несколько станций к партнёру; процент вознаграждения партнёра применяется к прибыли со всех привязанных станций.
5. При завершении аренды backend начисляет долю партнёра в баланс по проценту партнёра, действовавшему в момент завершения.
6. Баланс партнёра учитывает аренды только за период фактической привязки станции; отвязка/повторная привязка не пересчитывает прошлые начисления.
7. API отдаёт данные для списка станций партнёра, сводки за период и детализации по станции.
