## Проблема

- Пользователь у станции должен арендовать powerbank без отдельного мобильного приложения, прямо через терминал станции.
- Нужен основной поток (с созданием аккаунта по номеру телефона) и упрощённый поток для пользователя с разряженным телефоном.
- Оплата должна происходить картой непосредственно на терминале станции.

## Цель

- Дать пользователю возможность арендовать powerbank через экран станции: ввод номера, подтверждение SMS, привязка карты, оплата, выдача powerbank.
- Дать пользователю с разряженным телефоном возможность арендовать powerbank без ввода номера телефона и регистрации, через прямую оплату картой.

## Не входит в текущую итерацию

- Возврат powerbank через тот же экран (flow окончания аренды отдельно не описан).
- Управление тарифами аренды на стороне терминала.
- Поддержка нескольких языков интерфейса терминала.
- Альтернативные способы оплаты, кроме банковской карты.

## Триггер и аудитория

- Точка входа / триггер: пользователь подходит к станции и видит экран покоя с полем ввода номера и кнопкой альтернативного сценария.
- Основная аудитория: пользователи с рабочим телефоном, готовые получить SMS-код.
- Вторичная аудитория: пользователи с разряженным телефоном.

## Целевое поведение продукта

### Сценарий

1. Пользователь видит экран покоя терминала с полем ввода номера телефона и менее акцентной кнопкой альтернативного сценария (для разряженного телефона).
2. Пользователь вводит номер, подтверждает его кодом из SMS; система создаёт аккаунт по этому номеру, если его еще нет.
3. Пользователь прикладывает карту к терминалу; карта обрабатывается и сохраняется в аккаунте для будущих списаний.
4. После успешной оплаты пользователь получает SMS о создании аккаунта/начале аренды и получает powerbank из станции.

### Правила результата

- Powerbank выдаётся только после успешной оплаты.
- Аккаунт создаётся автоматически по номеру телефона при первом подтверждении SMS-кода.
- Карта сохраняется в аккаунте пользователя для последующих аренд.
- Для пользователя с разряженным телефоном powerbank выдаётся после оплаты картой без ввода номера и без регистрации.
- Пользователь получает SMS-подтверждение о создании аккаунта или начале аренды (основной поток).

## Бизнес-правила

- Ввод и подтверждение номера телефона выполняется через SMS-код (Twilio).
- Оплата на терминале выполняется через банковскую карту (Stripe).
- Альтернативный поток для разряженного телефона не создаёт аккаунт и не требует ввода номера.
- Один поток оплаты ведёт к выдаче ровно одного powerbank.

## Ограничения и известные лимитации

- Продукт / UX: на экране покоя кнопка альтернативного сценария должна быть менее акцентной, чем основное поле ввода номера.
- Биллинг / правовые ограничения: оплата картой проходит через Stripe; точная схема списания (предавторизация/прямой charge) не подтверждена.
- Технические ограничения, уже подтвержденные на продуктовом уровне: подтверждение номера телефона выполняется через SMS-код, отправляемый Twilio.
- Внешние зависимости: Stripe (оплата картой), Twilio (SMS-код и SMS-уведомления).

## Влияние на аналитику, CRM и коммуникации

- Аналитика: Не определено.
- CRM / подписочные системы: Не определено.
- Письма / уведомления: SMS о создании аккаунта/начале аренды и SMS-код подтверждения номера — через Twilio.

## Пограничные сценарии

- Пользователь вводит неверный SMS-код или код не приходит.
- Карта пользователя отклонена на этапе оплаты.
- Пользователь с разряженным телефоном прикладывает карту, которая ранее не использовалась в системе.
- Powerbank не выдаётся механически после успешной оплаты (отдельно не описано, но влияет на завершение сценария).
- Пользователь повторно подходит к станции с уже существующим аккаунтом и привязанной картой.

## Допущения

- "Терминал станции" — это экран самой станции, а не отдельное мобильное приложение пользователя.
- Карта, привязанная в основном потоке, используется банком-эмитентом Stripe для будущих списаний без повторного ввода.
- SMS-код подтверждения и SMS-уведомление о начале аренды — это разные сообщения.
