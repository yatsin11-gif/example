## Список задач

### Task 1

- Title: BE. Партнёры. Модель партнёра, станций и привязки с историей периодов
- Repository: `gozap-backend`
- Owner role: Backend engineer
- Зачем нужна задача: нужна основа данных для партнёров, привязки станций с процентом и историей периодов, на которой строится расчёт баланса и Stripe payout.
- Scope:
  - модель партнёра (логин, хэш пароля, имя, телефон)
  - модель привязки станции к партнёру с процентом и датами начала/конца периода
  - CRUD endpoints для создания партнёра, поиска/фильтрации, привязки/отвязки станции
- Out of scope: расчёт баланса, payout, FE
- Dependencies: нет
- Risks: точная схема станций (`gozap-backend`) не подтверждена в текущем контексте
- Definition of done: можно создать партнёра, привязать/отвязать станцию с процентом через API, история периодов сохраняется

### Task 2

- Title: BE. Партнёры. Расчёт баланса по завершённым арендам
- Repository: `gozap-backend`
- Owner role: Backend engineer
- Зачем нужна задача: при завершении аренды система должна начислять долю партнёра, активного на станции в момент завершения.
- Scope:
  - хук/обработчик на событие завершения аренды
  - определение активного партнёра станции на момент завершения по истории периодов
  - начисление доли в баланс партнёра без пересчёта при последующей отвязке
  - агрегация по периоду и станции для сводки
- Out of scope: Stripe payout, FE
- Dependencies: Task 1
- Risks: нет точного контракта события "аренда завершена" в текущем контексте
- Definition of done: баланс и агрегаты по периоду/станции корректно отражают только начисления за период привязки

### Task 3

- Title: BE. Партнёры. Ежемесячный Stripe payout и история выплат
- Repository: `gozap-backend`
- Owner role: Backend engineer
- Зачем нужна задача: накопленный баланс должен автоматически выплачиваться партнёру раз в месяц через Stripe, с сохранением истории.
- Scope:
  - хранение банковского счёта/карты партнёра (через Stripe)
  - ежемесячный scheduled job выплаты накопленного баланса
  - обработка отсутствия реквизитов на момент выплаты
  - история выплат (сумма, дата, статус) и обработка Stripe webhook о результате
- Out of scope: ручной запрос выплаты
- Dependencies: Task 1, Task 2
- Risks: точная Stripe-сущность для перевода (Connect/transfer) не подтверждена
- Definition of done: раз в месяц баланс партнёра с указанными реквизитами автоматически выплачивается, история обновляется по webhook

### Task 4

- Title: Admin. Раздел "Партнёры": список, создание, привязка станций
- Repository: `gozap-admin`
- Owner role: Frontend/Admin engineer
- Зачем нужна задача: администратору нужен UI для создания партнёра, поиска/фильтрации и управления привязкой станций и процентом.
- Scope:
  - форма создания партнёра
  - список партнёров с поиском/фильтром
  - UI привязки/отвязки станций с процентом
  - admin-зеркало данных кабинета партнёра
- Out of scope: кабинет партнёра
- Dependencies: Task 1
- Risks: нет

### Task 5

- Title: Admin. Кабинет партнёра: станции, сводка, выплаты, CSV
- Repository: `gozap-admin`
- Owner role: Frontend/Admin engineer
- Зачем нужна задача: партнёру нужен личный кабинет со списком станций, сводкой за период, деталями аренд, настройкой счёта, историей выплат и CSV-выгрузкой.
- Scope:
  - список станций партнёра (код, название, адрес, статус, аренды, вознаграждение за период)
  - сводка за период (баланс, ближайшая выплата, число аренд, сумма, разбивка по станциям)
  - детали станции: список аренд (дата, стоимость, вознаграждение) и итог
  - настройка банковского счёта/карты
  - история выплат и CSV-выгрузка
  - сброс пароля через SMS (зависит от `sa/docs/gozap/auth`)
- Out of scope: ручной запрос выплаты
- Dependencies: Task 1, Task 2, Task 3, `sa/docs/gozap/auth`
- Risks: нет

## Порядок поставки

1. Task 1 — модель партнёра/станций/привязки.
2. Task 2 — расчёт баланса.
3. Task 4 — admin UI поверх Task 1.
4. Task 3 — Stripe payout.
5. Task 5 — кабинет партнёра поверх Task 1–3 и SMS-авторизации.

## Cross-Repository Notes

- Task 5 зависит от `sa/docs/gozap/auth` для сброса пароля по SMS через Twilio.
- Видимость партнёрского раздела в `gozap-admin` может ограничиваться ролью (`sa/docs/gozap/admin-roles`), если такая зависимость подтвердится.
