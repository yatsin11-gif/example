## Проблема

- У администратора нет инструмента, чтобы завести партнёра, привязать к нему станции и задать процент вознаграждения.
- У партнёра нет личного кабинета, чтобы видеть свои станции, аренды и заработок.
- Выплаты партнёрам сейчас не автоматизированы и не имеют истории, доступной партнёру.

## Цель

- Дать администратору полный контроль над партнёрами и привязкой станций с индивидуальным процентом.
- Дать партнёру самостоятельный доступ к статистике своих станций, балансу и истории выплат, с ежемесячной автоматической выплатой через Stripe.

## Не входит в текущую итерацию

- Изменение процента партнёра самим партнёром.
- Ручной запрос выплаты партнёром (только автоматическая ежемесячная выплата).
- Многоуровневая партнёрская иерархия (под-партнёры).
- Уведомления партнёру по email/push о начислениях.

## Триггер и аудитория

- Точка входа / триггер: администратор создаёт партнёра в админке; партнёр получает логин/пароль и заходит в свой кабинет.
- Основная аудитория: администраторы платформы Gozap.
- Вторичная аудитория: владельцы точек (партнёры).

## Целевое поведение продукта

### Сценарий

1. Администратор создаёт партнёра (логин, пароль, имя, телефон) и привязывает к нему одну или несколько станций с индивидуальным процентом отчисления.
2. Партнёр логинится в свой кабинет и видит только свои станции, сводку за период и баланс.
3. Система автоматически считает долю партнёра по каждой завершённой аренде и добавляет её в баланс, учитывая период привязки станции.
4. Раз в месяц система автоматически выплачивает накопленный баланс на указанный партнёром счёт через Stripe; партнёр видит историю выплат и может выгрузить CSV.

### Правила результата

- Партнёр видит только данные своих станций, никогда — данные чужих точек или других партнёров.
- Баланс партнёра должен отражать только аренды за период, когда станция была привязана к нему.
- Выплата не должна происходить, если не настроен банковский счёт/карта партнёра.
- Администратор должен видеть те же данные, что видит партнёр (плюс собственные admin-only возможности).
- Сброс пароля партнёра выполняется по SMS на номер телефона партнёра (через Twilio).

## Бизнес-правила

- Процент вознаграждения задаётся отдельно для каждой станции, включая 0%.
- Отвязка станции от партнёра не пересчитывает прошлые начисления, привязанные к этой станции за период владения.
- Привязка одной станции допускается только к одному партнёру в один момент времени.
- Выплата партнёрам выполняется автоматически один раз в месяц через Stripe.
- Партнёр обязан указать банковский счёт/карту для получения выплат; это можно отредактировать позже.

## Ограничения и известные лимитации

- Продукт / UX: не определено, что происходит с балансом партнёра, если на момент ежемесячной выплаты не указан счёт получателя — открытый вопрос.
- Биллинг / правовые ограничения: выплаты обрабатываются через Stripe; точная схема Stripe-сущности (Connect account, payout, transfer) не подтверждена.
- Технические ограничения, уже подтвержденные на продуктовом уровне: расчёт доли партнёра выполняется системой автоматически по факту завершения аренды.
- Внешние зависимости: Stripe (выплаты), Twilio (SMS для сброса пароля).

## Пограничные сценарии

- Станцию отвязывают от партнёра и сразу привязывают к другому партнёру в середине периода.
- У партнёра нулевой баланс на момент плановой ежемесячной выплаты.
- Партнёр не указал банковский счёт к моменту плановой выплаты.
- Партнёру задают процент 0% для одной из его станций.
- Администратор ищет/фильтрует партнёра в большом списке.

## Допущения

- Один логин партнёра соответствует одному аккаунту-владельцу точки.
- CSV-выгрузка по заработку и выплатам формируется по тому же периоду, что выбран в сводке.
- "Сегодняшняя точка" = станция; "аренда" = завершённая аренда powerbank на этой станции.
