## Роли в админке — визуальный TL;DR

Источник: [../requirements/feature-spec.md](../requirements/feature-spec.md). Схема — краткая суть, детали в спеке.

### User flow (что видит пользователь)

```mermaid
flowchart TD
    A[Супер-админ: раздел Админы] --> B[Создать админа]
    B --> C[Выбрать уровень доступа]
    C --> D[Админ логинится]
    D --> E[Навигация показывает<br/>только разрешённые разделы]
    E --> F{Запрос к запрещённому разделу?}
    F -->|напрямую через API| G[Backend отклоняет запрос]
    F -->|через UI| H[Раздел скрыт, недоступен]
```

### Что внутри (pipeline)

```mermaid
flowchart LR
    SA[Супер-админ создаёт админа] --> ST1[(Admin record + access level)]
    ST1 --> NAV[Frontend: рендер навигации<br/>по access level]
    ST1 --> AUTH[Backend: проверка access level<br/>на каждом запросе]
    AUTH --> CHK{Доступ разрешён?}
    CHK -->|да| OK[Запрос выполняется]
    CHK -->|нет| DENY[403 / отказ]
```

> Этап в конвейере: **QA test cases готовы**, ожидает ручного QA review и Qase sync. См. [../../../PROGRESS.md](../../../PROGRESS.md).
>
> Открытые вопросы: точное количество уровней доступа кроме супер-админ/админ; может ли быть больше одного супер-админа (см. feature-criteria.md).
